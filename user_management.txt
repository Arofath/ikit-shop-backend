ដំណាក់កាលទី ៣៖ ការរៀបចំផ្ទាំង UI បង្កើត User (Frontend)
នេះជាចំណុចដែលយើងត្រូវរៀបចំនៅក្នុង AddAdminModal.vue ដើម្បីឱ្យ Admin ងាយស្រួលប្រើ។

ប្រអប់ Password ថ្មី (Hybrid Field)៖ អនុញ្ញាតឱ្យ Admin វាយអក្សរបញ្ចូលដោយដៃក៏បាន។

ប៊ូតុង Auto-Generate (🎲)៖ ដាក់នៅជាប់ប្រអប់ហ្នឹង។ ពេល Admin ចុច វានឹងបង្កើតលេខកូដស៊ាំញ៉ាំ (ឧ. v8$Pz2q!) រួចចាក់ចូលក្នុងប្រអប់នោះដោយស្វ័យប្រវត្តិ។

ប៊ូតុង Copy (📋)៖ សម្រាប់ឱ្យ Admin ចុច Copy យកលេខសម្ងាត់នោះទៅ Paste ផ្ញើក្នុង Telegram ឱ្យបុគ្គលិក។

Checkbox ជម្រើស៖ មានប្រអប់ធីកបញ្ជាក់ថា "តម្រូវឱ្យបុគ្គលិកប្តូរលេខសម្ងាត់ពេល Login លើកក្រោយ" (បើក On ជានិច្ចជាលំនាំដើម)។

ដំណាក់កាលទី ៤៖ ការស្ទាក់ចាប់នៅពេល Login (Authentication Logic)
នេះជាចំណុចសុវត្ថិភាពដ៏សំខាន់បំផុត។ យើងមិនអាចបណ្តោយឱ្យបុគ្គលិកចូលទៅកាន់ Dashboard ដោយប្រើលេខសម្ងាត់បណ្តោះអាសន្ននោះបានទេ។

ការងារនៅ Backend ពេល Login៖ ពេល User ចុច Login ប្រព័ន្ធនឹងឆែកមើល require_password_change។ បើវាស្មើ true នោះ Backend នឹងមិនទាន់ឱ្យ Token ពេញលេញទេ តែវានឹងបោះ Error កូដពិសេសមួយ (ឧទាហរណ៍ 403 Force Password Change) ត្រឡប់ទៅវិញ។

ការងារនៅ Frontend ពេល Login៖ ពេល Frontend ទទួលបាន Error នេះ វានឹងមិនលោតទៅផ្ទាំង Dashboard ទេ តែវានឹងរុញ (Redirect) User នោះទៅកាន់ទំព័រពិសេសមួយគឺ "ទំព័រកំណត់លេខសម្ងាត់ថ្មី"។

ដំណាក់កាលទី ៥៖ ទំព័របង្ខំឱ្យប្តូរលេខសម្ងាត់ (Force Reset Password Page)
នេះជាផ្ទាំងចុងក្រោយសម្រាប់បុគ្គលិកដែលទើបតែ Login លើកដំបូង។

ការងារត្រូវធ្វើ៖ បង្កើតទំព័រថ្មីមួយ (ឧទាហរណ៍ ForcePasswordChange.vue) ដែលមិនមាន Menu មិនមាន Sidebar គឺមានតែទម្រង់ឱ្យវាយលេខសម្ងាត់ថ្មីចំនួន ២ ដង (New Password និង Confirm Password)។

ដំណើរការបញ្ចប់៖ ពេលបុគ្គលិកចុច Save, វានឹងហៅ API ទៅកាន់ Backend ដើម្បី Update លេខសម្ងាត់ថ្មី រួចប្តូរតម្លៃ require_password_change ទៅជា false វិញ រួចទើបអនុញ្ញាតឱ្យចូល Dashboard ជាស្ថាពរ។
